# 04 · 部署上线到 Vercel

**目标**：得到一个公网网址（形如 `https://kaoyan-words.vercel.app`），
以后在手机、公司电脑、任何地方打开都能背单词。

**花费**：**0 元**。Supabase 免费版 + Vercel 免费版，都不需要绑卡。

> ⚠️ 说明：下面涉及三个网站的控制台操作。网站界面会不时调整，
> 如果某个按钮名字对不上，**别硬找，直接来问我**。
> 这些步骤我没法替你验证，但每一步「你应该看到什么」我都写清楚了。

---

## 前置条件清单

开始之前，确认这几件事都成立：

- [ ] 本地 `npm run dev` 能正常打开 http://localhost:3000
- [ ] 已经创建 Supabase 项目
- [ ] 已经在 Supabase 的 SQL Editor 里执行过 `supabase/schema.sql`
- [ ] 已经在 Supabase 的 SQL Editor 里执行过 `supabase/seed.sql`
- [ ] `.env.local` 填好了，且 http://localhost:3000/diagnostics 显示**绿色 ✅**

**最后一条最重要。** 本地都跑不通的话，部署上去只会更难查 ——
因为线上你看不到终端里的报错。

---

## 第 1 步：把代码推到 GitHub

现在这个仓库只在你的电脑上，还没有"远端"。Vercel 需要从 GitHub 拉代码。

### 1.1 在 GitHub 建一个空仓库

1. 打开 https://github.com ，登录或注册（免费）
2. 右上角 **+** → **New repository**
3. Repository name 填 `kaoyan-words`
4. 选 **Private**（推荐，反正是个人项目）或 Public
5. **不要**勾选 "Add a README file" / ".gitignore" / "license"
   （因为本地已经有这些文件了，勾了会产生冲突）
6. 点 **Create repository**

### 1.2 把本地代码推上去

创建完会看到一个空仓库页面，照着它的提示做，或者直接用下面这几条：

```bash
git remote add origin https://github.com/你的用户名/kaoyan-words.git
git branch -M main
git push -u origin main
```

> 第一次推送会让你登录 GitHub。Windows 上通常会弹一个浏览器窗口让你授权，
> 授权完就自动继续了。

### 1.3 推之前先确认密钥没被推上去

这一步我已经帮你在 `.gitignore` 里配好了，而且验证过：

```
✅ .env.local 未被跟踪
✅ node_modules 未被跟踪
仓库里最大的文件是 package-lock.json（256 KB）
.git 目录总共 0.5 MB
```

你自己也可以确认一下：

```bash
git status --short
```

**如果输出里出现 `.env.local`，先别推，告诉我。**

---

## 第 2 步：在 Vercel 导入项目

1. 打开 https://vercel.com ，点 **Sign Up** → **Continue with GitHub** 登录
2. 进控制台后点 **Add New...** → **Project**
3. 找到你的 `kaoyan-words` 仓库 → 点 **Import**

导入页面里，**Framework Preset 会自动识别成 Next.js**，不用改。
Build 命令、Output 目录也都不用改。

**先别点 Deploy** —— 下一步很关键。

---

## 第 3 步：★ 先填环境变量，再点部署

在 Import 页面往下找 **Environment Variables**（环境变量），展开它，
添加两条：

| Name | Value |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | `https://你的项目.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | `sb_publishable_xxxxx` |

**值和你本地 `.env.local` 里的一模一样。**

填完，再点 **Deploy**。

### 为什么必须「先填变量再部署」

这条一定要理解，否则你会浪费半小时：

> **`NEXT_PUBLIC_` 开头的环境变量，是在「构建时」被写死进代码里的，
> 不是运行时去读的。**

也就是说，如果你在没填变量的情况下先部署了一次，那份产物里就**永久写着
"没有配置"**。之后你再到 Vercel 设置里补上变量，也**不会自动生效** ——
必须**重新部署（Redeploy）**一次。

> 这正是我在代码里写 `isSupabaseConfigured()` 的原因：
> 它让"没配置"变成一张友好的中文提示卡，而不是一个白屏报错页。

**如果你已经踩了这个坑**：Vercel 项目页面 → Deployments → 最新那条右边的
**⋯** → **Redeploy**，即可。

## 第 4 步（可选）：配置 Supabase 的「允许的网址」

> **修正说明**：我最初把这一步写成了"必做"，后来在代码里核实过 ——
> **当前这套流程用不到它，可以直接跳过。** 下面是核实依据。

我们从头到尾没有使用任何"需要跳转"的登录方式：

| 功能 | 我们是否使用 | 会不会用到 Redirect URL |
| --- | --- | --- |
| 邮箱 + 密码登录 | ✅ 用 | ❌ 不涉及跳转 |
| 注册（已关掉邮箱验证） | ✅ 用 | ❌ 注册完直接返回会话，不发邮件 |
| 邮箱确认链接 | ❌ 没用 | — |
| 第三方登录（GitHub / Google） | ❌ 没用 | — |
| 魔法链接 / 找回密码 | ❌ 没用 | — |

验证方法：在项目里搜 `redirectTo` / `emailRedirectTo` / `signInWithOAuth`
是**搜不到任何结果的**（你可以自己试）。既然我们从没传过"跳回来要去哪"，
Supabase 也就没有东西可以校验，自然不会拒绝。

### 那什么时候需要回来配？

以后如果你要做这几件事，就必须回来配：

- 开启邮箱验证（Confirm email）
- 加"忘记密码"功能
- 加第三方登录（GitHub / Google 登录）

到那时：**Authentication** → **URL Configuration**

- **Site URL**：填你的 Vercel 网址
- **Redirect URLs**：把同一个网址加进去
- 本地开发用的 `http://localhost:3000` 也一起留着

## 第 5 步：验证线上版本

按顺序走一遍，每一步都要看到预期结果。

> 💡 下面这些大部分可以**自动检查**，一条命令跑完：
>
> ```bash
> npm run verify:deployed -- https://你的网址.vercel.app
> ```
>
> 它会检查：首页/登录页可用性、**环境变量是否在构建时正确内联**（部署最容易踩的坑）、
> 诊断页有没有真的连上数据库、未登录访问是否 307 跳转并保留 `?next=`、
> 响应头有没有泄露框架信息。

| 访问 | 应该看到 |
| --- | --- |
| `https://你的网址/diagnostics` | **绿色 ✅ 连接成功** |
| `https://你的网址/` | 如果没登录 → 跳到登录页（不是黄色"数据库还没配置"） |
| `https://你的网址/register` | 注册一个账号 |
| 注册后 | 能进首页，看到统计卡片（数字可能都是 0，正常） |
| `https://你的网址/study` | 出现一个单词 + 「显示释义」按钮 |
| 背两三个词 | 每点一次会跳到下一个，按钮下面显示"下次复习：X 天后" |
| **退出登录，再重新登录** | **进度还在** ← 这就是持久化验证 |
| 手机浏览器打开同一网址 | 界面正常，能背 |

**第 7 行是重点。** 这就是你从一开始就强调的"关闭浏览器、换设备后进度不丢"。

## 第 6 步（推荐）：解决"注册后收不到验证邮件"

Supabase 免费版自带的邮件服务**每小时只能发几封**。个人自用最省事的做法是
直接关掉邮箱验证：

**Authentication** → **Sign In / Providers** → **Email** →
关掉 **Confirm email**

关掉之后，注册完直接就是登录状态，不用去邮箱点链接。

> 副作用：别人用你的网址注册时，邮箱不需要验证就能用。
> 你这个是私人项目，无所谓。

## 以后怎么更新代码

改完代码之后：

```bash
git add -A
git commit -m "说明这次改了什么"
git push
```

Vercel 检测到 push 会**自动重新部署**，大约 1 分钟。
刷新网址就是新版了。

> 如果改的是**环境变量**，光 push 没用（变量不是代码），
> 要去 Vercel 设置里改，然后 **Redeploy**。

## 常见坑对照表

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 线上显示黄色"数据库还没配置" | 环境变量没填，或填了但没重新部署 | 补上变量后 **Redeploy** |
| 改了变量还是没生效 | `NEXT_PUBLIC_` 是构建时写死的 | 必须 Redeploy |
| 线上报"表不存在" | 建表语句没在**这个** Supabase 项目里执行过 | 在 SQL Editor 里跑 `supabase/schema.sql` |
| 部署失败（Build 报错） | 代码有问题 | 本地先跑 `npm run build`，本地过不了线上也过不了 |
| 注册后收不到邮件 | 免费版邮件限流 | 关掉 Confirm email |
| 一周没用后打不开 | Supabase 免费项目连续 7 天无访问会被暂停 | 去 Supabase 控制台点恢复 |
| 以后加了邮箱确认 / 第三方登录后跳转失败 | 那时才会用到 Redirect URLs | 见第 4 步 |
| 页面能打开但样式全丢 | 极少数情况 | 清一次浏览器缓存，或看 Vercel 构建日志 |

## 部署相关的技术细节（可选阅读）

### 为什么 next.config.ts 里有一行 `outputFileTracingIncludes`

`app/preview/study` 那个预览页会在运行时用 `fs` 读 `data/words-seed.csv`。
Vercel 会把代码拆成一个个"函数包"，只带真正用到的文件 —— 而它是靠分析
`import` 来判断的，`fs.readFile` 读的文件不属于 `import`。

我实测过：Next.js 的追踪器确实"猜"到了这个文件（构建产物
`.next/server/app/preview/study/page.js.nft.json` 里列着它），
所以**当前不会出问题**。

但"靠它猜对"和"明确告诉它"不一样，所以我在配置里写明了这条依赖。
哪天有人改了路径拼法导致启发式失效，预览页会静默坏掉 ——
而且本地开发完全看不出来（本地那个文件一直在）。

### `poweredByHeader: false`

默认情况下 Next.js 会在每个响应头里写 `X-Powered-By: Next.js`，
等于免费告诉别人你用什么框架。关掉它成本为零。
我在生产模式实测过：加之前有，加之后没有了。

### 怎么自己检查部署产物

构建之后可以看 Next.js 追踪到的文件清单：

```bash
npm run build
# 然后查看 .next/server/app/preview/study/page.js.nft.json
```

里面 `files` 数组就是这个路由部署时会带上的所有文件。
