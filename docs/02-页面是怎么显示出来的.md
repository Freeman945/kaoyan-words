# 02 · 页面是怎么显示出来的

这篇讲清楚一件事：**你打开一个网址，内容是怎么出现在屏幕上的？**

搞懂这个，你才能理解为什么代码里有些文件开头要写 `"use client"`。

---

## 一次页面请求，其实渲染了两次

这是最容易懵的地方。你以为"渲染一次"，实际是两次，而且分别发生在两台机器上：

```
第一台机器：服务器（你的电脑在跑 npm run dev，或者 Vercel 的机房）

  ① 收到请求
  ② 跑一遍你的组件代码
  ③ 产出一份完整的 HTML 字符串
  ④ 发给浏览器
        ↓
第二台机器：浏览器

  ⑤ 先把 HTML 画出来 → 你看到内容了（但按钮还点不动）
  ⑥ 下载 JS 文件
  ⑦ React 再跑一遍组件代码，把页面"接管"过来
        ↓
  ⑧ 现在按钮能点了
```

**第 ⑤ 步是为什么网页打开得那么快** —— 你看到的是服务器提前拼好的 HTML，
不是等 JS 下载完才渲染的。

**第 ⑦ 步叫 hydration（注水）** —— 一个挺形象的比喻：服务器给的 HTML 是"干的"
（好看但没行为），React 往里面注入 JS，让它"活"过来。

> 如果你在网页刚打开的一瞬间点按钮没反应，过零点几秒又能点了 ——
> 那就是你正好卡在第 ⑤ 步和第 ⑧ 步之间。这不是 bug。

## 两种组件：服务端组件 vs 客户端组件

React 19 / Next.js 里，组件分成两类。**默认是服务端组件。**

| | 服务端组件（默认） | 客户端组件（开头写 `"use client"`） |
| --- | --- | --- |
| 在哪里运行 | 只在服务器 | 服务器渲染一次 + 浏览器再跑一次 |
| 能读数据库吗 | ✅ 能 | ❌ 不能 |
| 能用密钥吗 | ✅ 能（密钥不进浏览器） | ❌ 不能（代码会被下载） |
| 能响应点击吗 | ❌ 不能 | ✅ 能 |
| 能用 `useState` 吗 | ❌ 不能 | ✅ 能 |
| 能让文件体积变小吗 | ✅ 代码不进浏览器 | ❌ 代码要下载 |

### 记忆口诀

> **服务端组件负责"数据"，客户端组件负责"交互"。**

### 本项目里谁是谁

**服务端组件**（负责取数据、拼页面）：

```
app/page.tsx             首页，读学习统计
app/study/page.tsx       背单词页，读今天该背的词
app/login/page.tsx       登录页外壳
app/diagnostics/page.tsx 诊断页，去试着连数据库
components/SetupNotice.tsx   纯静态提示（不需要交互，所以不用 "use client"）
components/SignOutButton.tsx 退出按钮（用表单，不需要 JS）
```

**客户端组件**（负责交互）：

```
components/StudySession.tsx     管"第几个词""释义显示没显示"
components/WordCard.tsx         有 onClick，要显示/隐藏释义
components/RatingButtons.tsx    有 onClick，三个按钮
components/AuthForm.tsx         有 useState，显示"提交中…"和错误
components/PreviewStudySession.tsx  预览页的外壳，提供"不写数据库"的保存函数
```

**看出来了吗**：`app/study/page.tsx`（服务端，取数据）把数据交给
`StudySession.tsx`（客户端，管交互）。这是最常见的搭配模式。

## 为什么非得分成两种？

因为有些事**只有服务器能做**，有些事**只有浏览器能做**。

### 只有服务器能做的事

```ts
// app/study/page.tsx  ← 服务端组件
const user = await requireUser();          // 读登录状态
const queue = await getStudyQueue(user.id); // 查数据库
```

如果让浏览器直接查数据库，就得把数据库密钥发给浏览器 —— **等于把家门钥匙
贴在门上**。所以查数据这件事必须留在服务器。

### 只有浏览器能做的事

```tsx
// components/RatingButtons.tsx  ← 客户端组件
<button onClick={() => onRate(button.rating)}>不认识</button>
```

服务器渲染完就把 HTML 发出去了，**它根本不知道你将来会点哪里**。
所以"响应点击"只能靠浏览器里的 JS。

---

## 两者的边界：什么东西能传过去？

从服务端组件往客户端组件传参数（props）时，有严格限制：

| 能传 | 不能传 |
| --- | --- |
| 字符串、数字、布尔、null | ❌ 普通函数 |
| 数组、普通对象 | ❌ `Date` 对象（要转成字符串） |
| `Map` / `Set`（较新版本支持） | ❌ 类实例 |
| **Server Action**（特殊：能传） | ❌ DOM 元素 |

**本项目里踩到过这个限制的地方：**

`app/study/page.tsx` 想给 `StudySession` 传一个"保存函数"：

```tsx
<StudySession items={items} onRate={submitReview} />
```

`submitReview` 是 Server Action，所以**可以**传。

但预览页 `app/preview/study/page.tsx` 想传一个"什么都不做"的本地函数 ——
**这就不行了**，本地函数没法序列化。所以多包了一层
`components/PreviewStudySession.tsx`（客户端组件），由它来提供那个函数：

```tsx
"use client";
export function PreviewStudySession({ items }) {
  return (
    <StudySession
      items={items}
      onRate={async () => {
        await new Promise((r) => setTimeout(r, 120));  // 假装在保存
        return { ok: true };
      }}
    />
  );
}
```

> 这就是为什么会有 `PreviewStudySession` 这个看起来"多余"的文件 ——
> 它是在绕过一个真实的技术限制。

## 一个你会好奇的现象：释义明明藏起来了，为什么源码里有？

这是之前验证时发现的。页面上的释义默认不显示，但在浏览器里按 `F12` 查看源码，
能搜到它：

```html
<script>self.__next_f.push([1,"...{\"meaning\":\"放弃；抛弃\"}..."])</script>
```

**原因**：React 在服务器渲染完之后，还要把客户端组件需要的数据一起打包发过去
（否则浏览器那边没法渲染第二个词）。这份数据叫 **RSC payload**。

所以：

- ✅ **视觉上确实藏住了** —— 渲染出来的 DOM 里没有释义
- ⚠️ **但数据在页面源码里** —— 因为不发给浏览器，切换单词就没法做

**所有客户端渲染的应用都是这样**，Anki、欧路词典也一样。想彻底藏住，
得改成"点了才向服务器要答案"，那每看一个词都要多等一次网络往返，
对天天要用的工具来说不划算。

我在 `components/ui.test.tsx` 里写了测试来确认这一点：

```tsx
it("还没点「显示释义」时，只有问题、没有答案", () => {
  const html = renderToStaticMarkup(<WordCard word={WORD} revealed={false} ... />);
  assert.ok(!html.includes("放弃；抛弃"), "释义在点击之前不应该出现在页面里");
});
```

注意这个测试渲染的是**组件**，不是整个页面 —— 所以它验证的是"渲染出来的
DOM 里没有"，这正是我们真正在意的。

## 为什么 `app/page.tsx` 要写 `export const dynamic = "force-dynamic"`

你会看到首页和背单词页都有这一行。它的意思是：**别把这一页提前生成成静态 HTML。**

因为 Next.js 很爱"偷懒"：如果一个页面在构建时不需要读 cookie，它就会提前生成
一份 HTML，之后所有人访问都返回这一份（这样最快）。

但首页显示的是"**你的**统计"，每个人、每一刻都不同。如果被预生成成一份固定
HTML，你刷新后看到的会是旧数字。

而且这里有个真实的坑：项目刚搭好、还没配 Supabase 时，首页会因为
`isSupabaseConfigured()` 提前返回，导致 `cookies()` 从没被调用过 —— Next.js 就
误以为这页跟用户无关，把它预生成了。结果就是**即使你后来配好了密钥，
首页还一直显示"数据库还没配置"**。

这个 bug 我在阶段 3 就发现并修掉了。凡是涉及登录状态的页面都应该写这一行。

## 小结

| 你可能想知道 | 答案 |
| --- | --- |
| 为什么打开很快？ | 服务器提前把 HTML 拼好了 |
| 为什么按钮一开始点不动？ | JS 还没下载完，React 还没接管（hydration） |
| 为什么有的文件要写 `"use client"`？ | 那个文件需要响应点击或用 useState |
| 为什么查数据库的代码都在某些文件里？ | 那些是服务端组件 / 服务端函数，只有它们能碰数据库 |
| 为什么释义在源码里？ | 数据要发给浏览器才能切换单词，所有客户端渲染应用都这样 |
