# 03 · 出问题时怎么排查

写代码一定会遇到报错。这篇的目标是：**让你不慌，知道从哪查起。**

---

## 排查心法：从最底层往上查

数据是从"数据库 → 逻辑 → 页面"一层层流上来的。所以**出问题也要从下往上查** ——
底下断了，上面怎么调都没用。

```
第 3 步：页面显示对不对？     ← 最后查这里
   ↑
第 2 步：逻辑算得对不对？     ← 再查这里
   ↑
第 1 步：数据库连通吗？表建了吗？  ← 先查这里 ★
```

**新手最常犯的错**：看到页面报错就去改页面代码。但十次里有八次，
问题在最底下的数据库。

---

## 第一步永远是：打开诊断页

### 👉 http://localhost:3000/diagnostics

这个页面就是为排查而生的。它会告诉你三件事：

| 显示 | 含义 | 下一步 |
| --- | --- | --- |
| ❌ 环境变量没配好 | `.env.local` 缺失或写错 | 照着 `.env.example` 填，然后**重启** dev server |
| 🟡 数据库连接成功（words 表还没建） | 密钥是对的，但没执行建表语句 | 去 Supabase SQL Editor 跑 `supabase/schema.sql` |
| ✅ 数据库连接成功，words 表可读 | 底层通了 | 问题在上面两层，继续往下看 |

**看到绿色 ✅ 再往下查。** 没绿之前别动代码。

## 症状对照表

### 🔴 打开网页一片空白 / 显示 500 错误

**先看终端**（跑 `npm run dev` 的那个窗口），不要只看浏览器。

| 终端里的错误 | 原因 | 解决 |
| --- | --- | --- |
| `缺少环境变量 NEXT_PUBLIC_SUPABASE_URL` | `.env.local` 没建或没填 | 参考 `.env.example` |
| `TypeError: fetch failed` | **网络问题，不是密钥问题** | 见下面「本机代理」一节 |
| `relation "public.words" does not exist` | 没执行建表语句 | 跑 `supabase/schema.sql` |
| `Invalid API key` | 密钥填错了（多空格/少字符） | 重新复制粘贴 |
| `Email address "..." is invalid` | 用了 `example.com` 这类保留域名 | 换真实域名 |

### 本机代理（会导致 `fetch failed`）

这台电脑通过 `127.0.0.1:7897` 上的代理上网，而 **Node.js 默认不读 Windows 的系统代理设置**，
它会直连出去 —— 结果是连接被重置，页面报 `TypeError: fetch failed`。

**最容易误判的地方**：同一时刻用 PowerShell 请求同一个网址是**能成功的**，
因为 .NET 会读系统代理。所以看起来像"网络没问题"，其实 Node 走的是另一条路。

**怎么区分**：把报错的底层原因找出来看 `code`——

| 底层 code | 含义 |
| --- | --- |
| `ECONNRESET` | 连接被重置 → 十有八九是没走代理 |
| `ENOTFOUND` | 域名不存在 → Project URL 写错了 |
| `401` / `permission denied` | 网络是通的，属于权限或密钥问题 |

**已经处理好了**：`npm run dev` 会经过 `scripts/dev.mjs` 自动带上代理设置。
如果代理端口换了，改 `.env.local` 里的 `HTTPS_PROXY`。

> 💡 **改完 `.env.local` 一定要重启 dev server。**
> 环境变量是启动时读入的，不重启不生效。这是最常见的"我明明改了啊"。

### 🔴 能打开，但数字全是 0

| 可能原因 | 怎么确认 |
| --- | --- |
| 还没导入单词 | Supabase → Table Editor → `words` 表看有没有数据。没有就跑 `supabase/seed.sql` |
| 登录的不是你以为的账号 | 首页顶部会显示当前邮箱，看一眼 |
| 时区判断问题 | 见下面"数字在特定时间不对" |

### 🔴 背单词时提示"保存失败"

| 错误信息 | 原因 |
| --- | --- |
| `登录状态已失效，请重新登录。` | cookie 过期了，重新登录 |
| `保存学习进度失败：...` | 后面的英文是数据库的原话，通常是表结构不对 |
| `保存失败，请检查网络后重试。` | 真的断网了，或者 Supabase 项目被暂停了 |

> Supabase 免费项目**连续 7 天没人访问会被自动暂停**。
> 如果你一周没用，回来发现连不上，去 Supabase 控制台点一下恢复就行。

### 🔴 数字在特定时间不对（比如早上的学习算成昨天）

**这是时区问题。** 服务器跑在 UTC，你在中国（UTC+8），差 8 小时。

这个坑我在 `lib/stats.ts` 里已经处理了（所有按"天"分组的计算都显式指定了
`Asia/Shanghai`），并且有 26 个测试盯着。但如果你以后改了哪个地方，
记得别把时区参数弄丢。

测试里有这么一条专门盯着它：

```ts
it("如果错用 UTC，今天的学习量会被算错", () => {
  assert.equal(summarizeProgress([], logs, NOW, SHANGHAI).reviewedToday, 2);
  assert.equal(summarizeProgress([], logs, NOW, UTC).reviewedToday, 1);
});
```

### 🔴 术语解释了但登录状态还是丢 / 老是掉登录

**九成是 `proxy.ts` 的问题。** 检查两件事：

1. 项目根目录的文件叫 `proxy.ts`，**不是** `middleware.ts`
   （Next.js 16 改了名，写成旧名字不会报错，但代码根本不执行）
2. 函数名叫 `proxy`，不是 `middleware`

这是 Next 16 最容易踩的坑。网上大部分 Supabase 教程还是旧写法。

## 改完代码后该跑什么

养成这个习惯，能挡掉绝大部分问题：

```bash
npx tsc --noEmit    # 类型检查：列名写错、参数写错，这里就报出来了
npm test            # 118 个自动化测试：算法、统计、界面、数据库安全
npm run lint        # 代码规范
```

**特别是 `tsc`。** 因为 `types/database.ts` 把表结构告诉了 TypeScript，
所以数据库列名拼错会在这里直接报错，不用等到点按钮才发现。

顺手记一句：

- 改了 `lib/spaced-repetition.ts` → 跑 `npm test`
- 改了 `supabase/schema.sql` → 跑 `npm test`（它会真的在本地 Postgres 里执行一遍）
- 改了任何 `.ts` / `.tsx` → 跑 `npx tsc --noEmit`

## 怎么自己加日志看数据

如果实在想不通，最直接的办法是**把数据打印出来**。

### 在服务器端代码里

```ts
// lib/progress.ts 里随便哪一行
console.log("准备写入的进度：", next);
```

然后看终端（`npm run dev` 那个窗口）。服务端的 `console.log` 出现在终端里。

### 在浏览器端代码里

```ts
// components/StudySession.tsx 里
console.log("当前是第几个词：", index);
```

然后按 `F12` → Console 标签页看。客户端的 `console.log` 出现在浏览器里。

**分不清该看哪边？** 记住：文件开头有 `"use client"` 的 → 看浏览器 Console；
没有的 → 看终端。

## 各页面的用途（别记混了）

| 页面 | 什么时候用 |
| --- | --- |
| `/diagnostics` | **第一站**。数据库连不上时先看它 |
| `/preview/study` | 不需要数据库的界面预览。想确认"是界面问题还是数据库问题"时用它 |
| `/study` | 真正背单词 |
| `/` | 看统计 |

**很有用的一个判断技巧**：

> 如果 `/preview/study` 能正常用，但 `/study` 不行 → 问题在**数据层**（数据库）。
> 如果 `/preview/study` 也白屏 → 问题在**代码**（界面或编译）。

因为预览页不碰数据库，它是个天然的"分界线"。

## 把项目恢复到一个干净状态

如果折腾乱了，想从头来过：

```bash
npm install          # 重新装依赖
npm run build        # 看能不能构建通过
```

想重置**数据库**（清空所有学习记录，重新开始）：

```sql
-- 在 Supabase SQL Editor 里执行
delete from public.review_logs;
delete from public.user_word_progress;
```

单词库不会被删掉（`words` 表没动）。

想彻底重来（连单词也删）：

```sql
delete from public.review_logs;
delete from public.user_word_progress;
delete from public.words;
```

然后再跑一遍 `supabase/seed.sql`。

## 出问题时的求助模板

如果你想问我（或搜资料），把这几样贴出来，能省很多来回：

```
1. 我在哪个页面、点了什么：/study 页面，点「不认识」
2. 期望的结果：进度保存成功
3. 实际看到：红色提示「保存学习进度失败：...」
4. 诊断页显示：✅ 数据库连接成功
5. 终端里的完整报错：（粘贴原文，不要只描述）
6. 浏览器 Console 里的报错：（如果有）
```

**第 5 条最重要。** 只说"报错了"和贴出原文，排查效率差十倍。

---

## 一句话总结

> **数据库 → 逻辑 → 页面，从下往上查。第一站永远是 `/diagnostics`。**
