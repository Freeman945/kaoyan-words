**让你能自己看懂、能自己改**。

## 项目全景：三个层次

整个项目只有三种角色，分得很清楚。**记住这张图，你就能找到任何一个功能在哪。**

```
┌─────────────────────────────────────────────────────────────┐
│  第一层：页面（app/）                                        │
│  负责「长什么样」。不管数据从哪来，也不管怎么存。              │
│                                                             │
│    app/page.tsx          首页 Dashboard                     │
│    app/study/page.tsx    背单词页                           │
│    app/login/page.tsx    登录页                             │
│    components/*.tsx      页面用的零件（单词卡、按钮…）         │
└───────────────────────────┬─────────────────────────────────┘
                            │ 调用
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  第二层：逻辑（lib/）                                        │
│  负责「规则」和「怎么读写数据」。这里没有一行界面代码。         │
│                                                             │
│    lib/spaced-repetition.ts  复习算法：下次该什么时候复习       │
│    lib/stats.ts              统计：今天学了多少、连续几天       │
│    lib/progress.ts           读写学习进度（唯一碰数据库的地方） │
│    lib/auth.ts               当前登录的是谁                   │
└───────────────────────────┬─────────────────────────────────┘
                            │ 通过 Supabase 客户端
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  第三层：数据库（Supabase）                                   │
│  负责「永久保存」和「保证安全」。                             │
│                                                             │
│    words                 单词库（大家共用）                    │
│    user_word_progress    你的学习进度（只有你能看）             │
│    review_logs           作答流水（只能追加，不能改）           │
│    行级安全策略（RLS）    数据库层强制"只能看自己的数据"         │
└─────────────────────────────────────────────────────────────┘
```

### 为什么要分成三层

不是为了"显得专业"，而是为了**改一个地方不用动其它地方**：

- 想改复习节奏（3 天改成 5 天）→ 只动 `lib/spaced-repetition.ts`，页面一行不用改
- 想改界面配色 → 只动 `app/` 和 `components/`，算法一行不用改
- 想换数据库 → 只动 `lib/progress.ts`

**判断一个功能该写在哪：**
- 它是"看起来怎样"吗？→ 第一层
- 它是"怎么算的 / 怎么存的"吗？→ 第二层

## 项目里的"专有名词"速查

| 名词 | 一句话解释 |
| --- | --- |
| **Server Component**（服务端组件） | 在服务器上渲染的组件。默认就是它。能直接读数据库、能拿密钥，但**不能**响应点击。 |
| **Client Component**（客户端组件） | 文件开头写了 `"use client"` 的组件。能响应点击、能用 useState，但**不能**直接读数据库。 |
| **Server Action** | 标了 `"use server"` 的函数。让浏览器能"像调用普通函数一样"调用服务器上的代码。写数据必须用它。 |
| **RLS**（行级安全策略） | 数据库对每一行数据的检查规则。保证 A 用户读不到 B 用户的数据。 |
| **upsert** | "有则更新、无则插入"的数据库操作。 |
| **hydration**（注水） | 浏览器拿到服务器发来的 HTML 后，React 接管页面、让按钮变得可点击的过程。 |
| **proxy.ts** | Next.js 16 里每个请求最先经过的文件（旧版叫 `middleware.ts`）。 |
